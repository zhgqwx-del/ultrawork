# 讨论与架构决策

每项变更从 `changes/<id>/change.md` 进入。将影响本次范围、方案或验收的资料列在「关联讨论与 ADR」下，链接到实际文件或工单。正文只保留本次影响和未决事项，讨论过程与长期约定各自维护。

Ultrawork 的讨论与架构决策分别登记在[讨论索引](../discussions/README.md)与 [ADR 索引](../decisions/README.md)。新文件沿用各索引的格式和编号。

## 何时单独记录

| 情况 | 记录位置 |
| --- | --- |
| 只影响本次变更，能在一次评审中决定的问题 | 写入本次 `change.md`，实现细节放在 `tasks.md` 或 `design.md` |
| 跨角色、团队或变更，需要多轮评审、比较备选方案，或需要持续跟踪证据 | 优先复用[已有讨论](../discussions/README.md)，新讨论放在 `docs/discussions/` |
| 会约束后续变更的架构、契约、数据或运维决策 | 查阅 [ADR 索引](../decisions/README.md)及其中的模板，新决策放在 `docs/decisions/` |

一次跨团队讨论可以先比较多个方案，再形成 ADR。只有本次有效的选择可在讨论中链接回变更及最终方案。后续变更直接引用仍生效的 ADR。

## 链接与归档

- 在变更的「关联讨论与 ADR」中链接讨论和 ADR 的真实路径，并简述它们影响了哪条规则或方案。讨论和 ADR 可链接回相关变更。已有决策覆盖本次需求时，可直接链接既有 ADR。
- 从 `changes/<id>/` 归档到 `changes/archive/<id>/` 后，检查变更目录内所有指向外部文件的相对链接，并同步修正讨论、ADR 或索引指回旧位置的链接。保留变更和 ADR 的编号，核对归档后的目标可打开。
