# 044 — 跨会话产物泄漏（共享工作区 + mtime 时间窗归属，并发写误判）

> 状态：**🟡 方案待拍板（候选 A 安全半减法 / 候选 B 标注不删，取舍见 §八）/ 未实现（本轮不改代码）** · 更新 2026-07-24（原草案 2026-07-19）
> 根因层级：**已代码 + 真实 mtime 双重确证**（确定性逻辑局限，非概率抖动）。
> 触发面：两个会话**共用同一 workspace** 且**写文件的时间相互重叠**时，B 会话写的文件被误算作 A 会话的产物。
> 影响范围：仅「产物 / 本轮产物」的**归属展示**（不影响文件本身、不影响「工作区」原始文件浏览器、不造成数据损坏）。
> 关联：ADR-048（产物预览/归属）· ADR-051（IM 会话 idle 轮转 + 侧栏发现性）· 归属实现 `lib/use-session-artifacts.ts` + `lib/turn-artifacts.ts` + `src-tauri/src/lib.rs` `scan_workspace_changes`。
> **与本次 HTML 预览 / deckcraft 居中改动无关**（git 确认这些归属文件本轮未被触碰）。

## 一、缘起（现象）

会话「用deckcraft重新生成codex.html」（今天 09:48 收尾）的右栏「产物」与转录「本轮产物」中，出现了 **`luxun.html`** —— 而它是**另一个会话「鲁迅介绍HTML页面」**的产物，本会话从未生成它。

同时右栏「工作区 `workspace1`」列出了 `luxun.html` / `lu_xun.html` / `shenzhen.html` / `tank-battle.html` / `opencode.*` / `remote-collab.*` 等一大批文件。

**先分清两个区域（重要）**：
- 「**工作区**」= 共享工作目录的**原始文件浏览器**，所有会话共用同一个 `workspace1/`，列出目录里全部文件是**设计如此、非缺陷**。
- 「**产物 / 本轮产物**」= 本应**按会话隔离**的派生视图。`luxun.html` 泄漏进这里，才是本 bug。

---

## 二、根因（逐环佐证，已确证）

### 2.1 隔离机制的两步

`lib/use-session-artifacts.ts`：

1. **baseline** = 本会话最早消息时间（`messages` 里最小 `time.created`）。
2. **扫描**：`invoke("scan_workspace_changes", { dir: directory, sinceMs: baseline })` —— Rust 侧 `walk` **整个 workspace 目录**，收集所有 `mtime_ms >= since_ms` 的文件（`src-tauri/src/lib.rs` 的 `scan_workspace_changes`）。
3. **按会话过滤**：`filterScanByWindows(hits, windows)` —— 只保留 mtime 落在**本会话某个 turn 时间窗**内的文件（`sessionTurnWindows`）。注释原文：「sessions sharing a workspace don't show each other's outputs (mtime baseline alone can't tell them apart)」。
4. **归属到轮**：`turn-artifacts.ts` 的 `turnIndexForMtime` 把每个扫描命中按 mtime 落进哪个 turn 窗，挂到该轮的「本轮产物」。

### 2.2 死穴

隔离**完全依赖「mtime 是否落在本会话 turn 窗内」**。而 turn 窗是**真实墙钟时间区间**（一个 turn 从首条消息 `created` 到末条 `completed` + grace）。因此：

> **只要另一个会话在本会话某个 turn 窗的时间区间内写了文件，该文件的 mtime 就落进本会话窗口 → 通过 `filterScanByWindows` → 被误算作本会话产物。**

mtime 只记录「文件何时被改」，**不记录「谁改的」**——原理上无法区分同一共享目录里另一会话的并发写入。turn-window 过滤是尽力而为的缓解，对**时间重叠的跨会话写**必然失效。

### 2.3 真实 mtime 佐证（为何只有 luxun.html 漏）

| 文件 | mtime (2026-07-19) | 落在 codex 会话窗（≈09:42–09:48）? | 结果 |
|---|---|---|---|
| **luxun.html** | **09:42:00**（另一会话写）| ✅ 落窗内、≥ baseline | **泄漏** |
| codex.html / codex.pdf | 09:47:47（本会话写）| ✅ | 正确归属 |
| lu_xun.html | 06-06 | ❌ mtime < baseline | 正确过滤 |
| shenzhen.html / tank-battle.html | 06-06 | ❌ | 正确过滤 |
| opencode.html | 07-18 | ❌ | 正确过滤 |

老文件因 `mtime < baseline` 在扫描阶段就被排除——**这精确解释了为何同在工作区的一堆 html 里，唯独 09:42 写的 luxun.html 漏了**。

### 2.4 触发条件

两个会话**共用同一 workspace** + **写文件时间重叠**。本例：用户约 09:42 在「鲁迅」会话生成 luxun.html，而 codex 的 deckcraft 长流程（~6 分钟）正在跑 → 撞进 codex 的 turn 窗。单会话、或会话间无时间重叠时不触发。

## 三、影响评估

- **仅归属展示错**：产物卡/本轮产物多出一张别的会话的卡。点开它会预览那份 HTML（内容真实存在于共享工作区）。
- **不损坏数据**、不误删、不影响「工作区」文件浏览器、不影响文件本体。
- **误报方向**：只会把别的会话的文件**多算进来**（false positive），不会漏掉本会话自己的产物。
- 严重度：中低（观感/信任问题，非数据安全）。但对「产物 = 本会话交付物」的语义是实打实的破坏。

## 四、候选解法（均未实现，待评估权衡）

### A. 会话级 workspace 子目录隔离
每个会话在 workspace 下有独立子目录，扫描只扫本会话子目录。
- ✅ 根治：物理隔离，mtime 归属不再跨会话。
- ❌ 改动大：改变文件落地位置与 UX（用户/agent 现在把文件写在 workspace 根）；跨会话「共享同一批文件」的现有用法被打破；deckcraft 等技能的输出路径约定要跟着改。

### B. 仅归属本会话工具/进程碰过的文件
放弃「盲扫 workspace」，只认本会话 `write/edit` 工具 + 已知子进程写的文件。
- ✅ 无跨会话泄漏。
- ❌ **废掉扫描的初衷**：扫描正是为了抓**不走工具调用**的 bash/python 副作用产物（如 deckcraft 经 python 导出的 deck.html/pdf/pptx）。改成纯工具归属会让这类产物**从产物面消失**——比多显一张卡更糟。

### C. 写入时给文件打会话标记
产物写入时落一个 manifest（或 xattr）记录 `sessionId`，归属按标记而非 mtime。
- ✅ 较稳，保留盲扫能力。
- ❌ 侵入：需要在所有产物写入路径（含技能子进程）注入标记；xattr 跨平台语义不一（NTFS/APFS/ext4）；manifest 需维护一致性。

### D. 缓解（非根治）：并发写去重启发式
扫描命中若其 mtime 同时落在**多个并发活跃会话**的窗口，标记为「不确定归属」降级处理。
- ✅ 改动小。
- ❌ 治标：需要「其它会话此刻是否活跃」的全局视图（当前 hook 只见本会话）；仍会在「另一会话已结束但 mtime 落窗」时误判。

**倾向**：A 最干净但代价高；B 有明确反效果不可取；C 最平衡但侵入。需先定「workspace 到底是会话私有还是共享」这个产品语义（ADR-051 已指出发现性/隔离是纠缠问题），再选路。

## 六、候选方案 A —— 「安全半减法」（按当前文件内容的作者归属）

> 状态：**候选（非选定）**，与候选 B（§八·四）二选一，取舍见 §八。

前置：workspace = **多会话共享**、本轮**只出方案不实施**（见 §五拍板）。在共享语义下保留盲扫、只修**扫描派生**那一半的错误归属（工具派生半读本会话消息、天生正确，不动）。

### 6.1 不可破坏的安全不变量
现行代码有一条安全性质：**误报只会「多显」，永不「漏显」本会话产物**（见 §三·§六五）。任何修复**必须守住它**——宁可残留少量泄漏，绝不隐藏本会话真实产物（漏显方向更坏、且破坏「产物=交付物」信任）。

### 6.2 归属判据：按「当前字节是谁最后写的」
把问题从「谁曾写过 `p`」重述为「**`p` 当前这份内容是谁最后写的**」（产物卡点开预览的正是当前内容）。据此：

> 扫描命中 `p`（本会话仅靠 mtime 落 turn 窗持有）从本会话产物中**剔除**，当且仅当**三条全满足**：
> 1. **另有会话**用写文件族工具（write/edit/输出类，复用现有 `FILE_TOOL_SUFFIXES` / `OUTPUT_TOOL_SUFFIXES`）认领了 `p`；且
> 2. 该工具事件时间戳与 `p` 的 `mtimeMs` **相符**（`|Δ| ≤ ε`，ε 取 `TURN_GRACE_MS`≈5s 量级；workspace 为本机、fs mtime 与 opencode 事件同机时钟，偏差小）；且
> 3. `p` **不在本会话的工具派生产物**里（本会话自己没用工具认领它）。
>
> 否则**保留**（默认多显，守 §6.1）。

**判据 2 是关键**（区别于上一轮被否的 naive 减法）：mtime 匹配到别家写工具事件 ⇒ 当前字节确由那家最后写入 ⇒ 剔除不会隐藏本会话产物：
- 若本会话**子进程**才是最后写入者，其 mtime **不会**匹配任何别家工具事件 → 不剔除 → 保留（不变量成立）。
- 若本会话曾用工具写更早版本、被别家工具覆盖（mtime=别家事件）→ 当前字节已是别家的、本会话那版已不存在 → 不显示**才正确**，非假阴性。

### 6.3 为何能修好旗舰案例（luxun.html）
鲁迅会话经 write/html 工具产出 `luxun.html`（mtime≈09:42），其工具事件时间≈mtime → 判据 1+2 命中；codex 会话判据 3 成立（codex 从没工具认领 luxun）→ 从 codex 产物**剔除**。codex 自己的 `codex.html/pdf`（deckcraft 子进程写、mtime 09:47）无任何别家工具事件匹配 → **保留**。✓

### 6.4 覆盖边界（诚实声明：欠覆盖 ≠ 衰退）
守不变量的代价是**只修得动「干净」的一类泄漏**，以下情形**不修、但也绝不误伤**：
- 泄漏源在**别的会话里也是子进程写、全局无任何工具认领**（如两个并发 deckcraft 各自 python 导出）→ 判据 1 不成立 → 保留泄漏。**原理性残余**（作者信息已丢，无法区分）。
- 别的会话**未被 viewed / 已被 LRU 淘汰 / 是 ACP 会话** → 不在全局 `messageCache`（`use-session-messages.ts`：全局监听只折叠 viewed 会话「M1」+ `MESSAGE_CACHE_LIMIT` LRU + ACP 不在全局流）→ 判据 1 无从判 → 保留泄漏。**IM/channel 驱动、从未在 UI 打开的并发会话属此类。**
> 全部残余方向一致 = **仍是 false-positive（多显）**，绝无 false-negative。属「修一部分、不引入任何新坏」。

### 6.5 被否决的更激进版本（存档，防回潮）
- **naive 无条件减法**（扣掉其它会话认领的所有路径）：A 子进程产出 `report.md`、B 工具也碰过同名 → 被减掉 → **A 丢真产物**（假阴性），破坏 §6.1。否决。
- **「本会话该窗口无子进程工具才减」**：deckcraft 长 turn 恰含 python-via-bash → 判据恒假 → **修不动旗舰案例**（该场景正是子进程活跃窗）。既无修复力又不比 6.2 更安全，否决。

### 6.6 反应性 / 触碰面（比上一轮方案更小）
因 6.2 只会「移除错显」、**永不隐藏真产物**，读非反应式的模块级 `messageCache` 带来的**滞后可接受**（泄漏晚一个 turn 自清）→ **无需**给 `messageCache` 加版本号。上一轮方案里最敏感的改动（动有竞态史 discussions/022 的 load-bearing 缓存）**移出范围**。

触碰文件（**Rust / 写路径 / 物理布局全部不动**）：
| 文件 | 改动 |
|---|---|
| `lib/use-session-artifacts.ts` | 构造 `foreignClaims`（跨 cached 会话的 {path→写工具事件时刻}）；按 6.2 过滤 `scannedPaths`；同规则传入 per-turn attribution |
| `lib/turn-artifacts.ts` | `attributeArtifactsToTurns` 用**同一判据**过滤 `scanHits`，保 sidebar 与转录一致（见该文件顶部「一份数据两个视图不能各说各话」警告） |
| `components/session/artifacts-panel.tsx` | 新增 helper：从消息取写工具事件 `{path, writeTimeMs}`（复用 `FILE_TOOL_SUFFIXES`/`OUTPUT_TOOL_SUFFIXES`/`PATH_PARAMS`/`toRelative`） |
| `lib/use-session-messages.ts` | **仅新增只读**访问器导出 cached 会话快照；不改缓存写逻辑、不加版本号 |

## 八、三轴残余分析 + A/B 取舍（**待拍板**）

问题：「路 A 是否零风险 / 零完备性衰退 / 零新体验缺陷？」——逐轴攻击后**答案是「不」**。路 A 相比现状**严格更安全、并消除已报告的那类泄漏**，但三轴均有**极窄残余**（据实标注，不为方案背书）：

### 8.1 完备性（假阴性）—— 非零，但比所修 bug 窄得多
存在**不可消除的「ε 同路径」角落**：若两会话在 `~ε`（≈`TURN_GRACE_MS`≈5s）内写**同一路径** `p`，而**本会话子进程才是当前字节的真正写入者**、偏偏别家写工具事件也落在该 ε 内 → §6.2 判据 2 命中 → 路 A 判给别家 → **隐藏本会话真产物**。
- 今天**永不发生**（今天只多显）→ 这是路 A **新引入**的失败角。
- 触发需 **同路径 + 同 ~5s + 跨会话** 三者并发，远比原 bug 罕见，但**非零**。
- 要压到字面零，只能「不删、改标注」（=候选 B）——作者信息已丢、ε 内先后不可判，任何删除都赌不过此角。

### 8.2 新体验缺陷 —— 有一个：闪烁 / 不稳定
`foreignClaims` 读的是**非反应式、会 LRU 淘汰**的 `messageCache`。一张跨会话卡可能：显示 →（B 消息入 cache）被删 →（B 从未 viewed / 被 LRU 挤掉）**再现**。
- 今天是「**稳定地错**」（卡一直在）；路 A 变「**时有时无**」。稳定-错 → 闪烁，是**新**观感瑕疵，`unread` 徽章随列表抖动而抖（`use-artifact-unread.ts:53` 直接数 `artifacts`）。
- 非正确性衰退，但确是今天没有的体验缺陷。

### 8.3 性能 —— 待实测的风险，非免费
`foreignClaims` = 每次扫描对**所有 cached 会话**跑 `extractArtifacts`（正则扫消息输出）。该管线代码明确**帧预算敏感**（`use-session-artifacts.ts` byTurn 缓存注释：+105% = 掉帧）。必须按 cache 版本 memo 才可控，而该版本信号**现不存在**。**实测前不能宣称零性能风险。**

### 8.4 候选方案 B —— 「标注不删」（把隔离问题降级为标注问题）
不移除跨会话命中，而在该卡上**标注**「来自其它会话 / 其它会话也在写」。判定复用与 §6.2 相同的 `foreignClaims`，只改**表达**、不改**列表身份**（`ordered` 不变）。
- ✅ 完备性衰退**字面零**（从不移除任何东西）。
- ✅ 无隐藏、无闪进/闪出（卡始终在，仅标注变化）。
- ✅ 性能影响更小（不改 `ordered` 身份 → 不扰动 unread 计数 / 预览 prev-next 导航）。
- ❌ **不消除**多显——那张别家卡仍在，只是不再被误认作本会话产物。
- 缩减测试矩阵：①标注命中判定正确（等价 T1 判定但断言「标注」而非「移除」）；②从不移除任何 artifact（守 `ordered` 身份）；③cache 只有本会话 / 退化不崩（等价 T4）。

### 8.5 取舍表（待拍板）

| 轴 | 候选 A（删除） | 候选 B（标注不删） |
|---|---|---|
| 完备性衰退 | 极窄 ε 同路径角落**非零** | **字面零**（从不移除） |
| 新体验缺陷 | 闪烁 + 徽章抖动 | 无隐藏；仅多一个标注 |
| 性能 | 需 memo，实测才敢下结论 | 更小（不改列表身份） |
| 消除「多显」 | **是**（卡消失） | **否**（卡在、被标注） |
| 一句话 | 更干净，但赌一个极窄角落 + 接受闪烁 | 绝不出错，但不消除、只降级表达 |
