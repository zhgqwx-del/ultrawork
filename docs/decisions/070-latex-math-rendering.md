# ADR-070：数学公式（LaTeX）渲染 —— 裸装 remark-math + rehype-katex，零启发式

- 状态：已接受（**真机验收通过**，2026-07-27）
- 日期：2026-07-27
- 相关：discussions/055（完整调研与四轮方案演进）· ADR-064（`rich-output.ts` 系统提示注入点）· ADR-050 / discussions/033（IM 出站净化）· gotchas §18 · conventions §19

## 背景

用户提供两张真机截图对比（同一问题「拒绝采样是指?」、同一模型 qwen3.7-max）：对照产品把公式渲染成数学排版，本项目**原样吐出美元符号源码**。

根因四层，全部实测（用项目实际在用的 `react-markdown@9.1.0` + `remark-gfm@4.0.1` 复现，非读码推断）：

1. **管线里没有任何数学插件** —— `message-parts.tsx` 的插件数组只有 `[remarkGfm]`，全仓 grep `latex|katex|mathjax` 在产品代码零命中。
2. **降级后连「原样显示」都做不到** —— `$\frac{p(x^*)}{M \cdot q(x^*)}$` 的两个 `*` 被 GFM 配对成 `<em>`，星号消失、斜体下的 `\` 看着像 `|`，与截图逐字符吻合。另一类是 `\{ \_ \%` 被 CommonMark 转义吞掉，而 `\cdot`/`\frac` 不受影响（`c`/`f` 非可转义标点）⇒ **损伤是选择性的**。
3. **`\(...\)` 在解析期即被销毁** ⇒ 任何修复必须发生在 markdown 解析之前或之内，渲染后 DOM 补救不可能。
4. **prompt 从未约定公式格式** —— `rich-output.ts` 的 `<output_format>` 规定了图片语法却一字未提公式。

## 决策

### D1：裸装 `remark-math`（默认配置）+ `rehype-katex`，不写任何启发式

`singleDollarTextMath` **保持默认 `true`**（接受单 `$`），`throwOnError:false` + `strict:false`。落在 `message-parts.tsx`（聊天）与 `artifact-preview.tsx`（`.md` 产物预览）两处 —— 全仓仅这两处 `<ReactMarkdown>`。

**这是三次自我推翻后的结论，前三版都更复杂且更差**（详见 discussions/055 §十）：

| 版本 | 方案 | 被什么推翻 |
|---|---|---|
| 初版 | 保留单 `$` + mdast 层货币守卫 | micromark 贪婪配对会偷走真公式的定界符，mdast 层已太晚 |
| 二版 | 保留单 `$` + 分词前字符串守卫 | 第一版实现即误杀真公式并向界面漏出 `\5` 脏字符 |
| 三版 | `singleDollarTextMath:false` + prompt 引导 `$$` + 白名单救援 | P0 实测引导只到 82.4%、混用 4/12 ⇒ 把模型智力变成单点依赖 |
| **定稿** | **裸装，零启发式** | 真实语料实测 **279 个公式零误伤** ⇒ 三版赖以成立的前提本身不成立 |

关键取舍是**失败模式的方向**，以及一个被数据推翻的假设：

- 前三版都在防御「货币误伤」（`$5 … $10` 配成公式），而该风险**从未用真实语料验证过**。拿 P0 产出的 **24 个真实模型回答 / 279 个公式**跑裸装管线：**真实误伤 0**（4 个疑似经复核全是真公式）。
- 为防御它而关掉单 `$`，代价是把渲染正确性绑死在模型行为上 —— 实测 qwen3.7-max **85% 的公式用单 `$`**，prompt 明确要求 `$$` 也只到 82.4%，且 **4/12 的回答混用两种定界符**（同一条回答一半渲染一半不渲染，观感比全不渲染更差）。

⇒ **副作用的严重性必须先用真实语料量化，再决定为它付多少复杂度**，否则防御本身成为更大的风险源。

### D2：KaTeX 而非 MathJax；`\(...\)` 不支持

KaTeX 自带字体、跨端确定性一致（项目要求三平台一致，ADR-037）；MathJax 的体积/性能优势不存在，且**换渲染器救不了 `\(...\)`** —— 定界符由 `remark-math` 的**分词层**决定，不在渲染层。`\(` 因根因 3 无解，只能靠 prompt 劝阻（qwen 实测 0 次使用，GPT 系有此习惯）。

### D3：修 IM 出站的公式篡改（独立既存缺陷，一并做）

`wechat-adapter.ts` 的 `stripMarkdown` 用裸正则剥离强调，`_(.+?)_` **跨公式配对**，把 `$\sum_{i=1}^{n} a_i = b_i$` 发成 `$\sum{i=1}^{n} ai = b_i$` —— 求和下标丢失、`a_i` 变 `ai`，**数学含义在出站前被改变**。

与根因 2 同源，但**桌面端有 CommonMark 的 intraword 保护、IM 端的裸正则没有** ⇒ IM 端更严重：桌面端只是显示难看，IM 端是内容错误。修法是公式区段先占位、剥离强调后再还原。**该缺陷独立于本 ADR 存在，本来就该修。**

### D4：两条 CSS 兜底 KaTeX 自身的缺口

- `.katex-display{overflow-x:auto}` —— KaTeX 带 `white-space:nowrap` 却不带任何 overflow 规则，超宽块级公式会撑破正文列或被裁（而修复前的源码形态会折行、内容全可见）。**副作用是好的**：公式外部宽度被锁在列宽内，顺带消除了流式期间的横向抖动。
- `.katex-mathml{user-select:none}` —— KaTeX 把公式输出三份（MathML + `<annotation>` 原文 + 可视 HTML），拖蓝选中会复制到三重重复。用 `user-select` 而非 `display:none`，MathML 要留在无障碍树里。「复制整条回答」按钮不受影响（走 `answerText` 原文）。

## 后果

**正面**：截图里的全部失败案例修复；顺带消除根因 2 的源码破坏；顺带修掉 IM 侧一个内容篡改缺陷；对模型行为零依赖，换模型不影响正确性。

**这不是纯加法** —— 四处体验衰退（discussions/055 §七之前）：W1 长公式横向溢出（已用 CSS 处置）· W2 流式抖动（实测块级公式宽度 0 次变化、高度 3 次，温和）· W3 局部选中复制丢失 LaTeX 源码（不可避免，对照产品同样）· W4 非法公式由源码变红字（可接受）。

**成本**：桌面包体积 +~590KB（katex.min.js 272KB + CSS 24KB + woff2 296KB，未压缩）；流式每帧 +1.6ms（最坏 42 公式样本，0.75→2.35ms，远在 60fps 的 16.7ms 预算内）。

**已知残留**：英文/金融语境的货币误伤未测（P0 语料全中文数学题）· 字体打包了 woff/ttf 冗余 876KB（三平台 WebView 全支持 woff2，可选优化）· 超宽公式被裁时无「可横向滚动」的视觉提示（罕见，实测真实语料不触发）。
