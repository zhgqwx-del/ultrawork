# 视觉审查 — 机器 rubric + 概念终审（Phase 5 用）

> 原则：**生成者不自评**。截图必须交给一个不带生成上下文的独立评审
> （有子代理工具就并行派发，每个评审 3-4 页；没有就在新的干净视角下逐页过），
> 避免"自己看自己怎么看都顺眼"的确认偏差。

## 一、逐页 rubric（每条二值判断，输出 JSON）

对每页截图回答（`export/shots/pNN.png`）：

| # | 判断 | fail 判据 |
|---|---|---|
| R1 | 文字完整 | 任何文字被裁切/省略号截断/叠出容器 |
| R2 | 无重叠 | 元素相互压盖（阴影/刻意叠层除外——本 skill 禁阴影，即全部算 fail） |
| R3 | 呼吸感（双边） | dense 页留白 <20%（过挤）**或 dense 页留白 >60% / 要点 <3（过稀，应 densify——补点或换更密版式，见 content-engineering §5.2）**；breathing 页留白 <50% |
| R4 | 对比可读 | 正文与底色对比不足（眯眼测试：结构消失） |
| R5 | 对齐 | 明显断裂的对齐线（左缘/基线参差） |
| R6 | 图文比例 | 图标/图片过大压过内容，或装饰性元素喧宾夺主 |
| R7 | accent 纪律 | accent 色出现 >2 处 |
| R8 | 一致性 | 与其他页并排看像不同 deck（字号层级/间距节奏漂移） |

输出：`{"page": N, "verdict": "pass|fix|needs_human", "findings": ["R1: …"]}`
写入 `qa_report.json` 的 `visual` 段。**receipt 等式：有 verdict 的页数 === 总页数**，缺一页即整体 fail。

## 二、修复纪律

- `fix` 判定的页：只允许改**该页** HTML 的定位/间距/字号档（ramp 内换档），
  不许重写内容、不许动 spec_lock/tokens。改后重截图重评该页。
- **回炉 ≤1 轮**；仍不过 → `needs_human`，交付时如实列给用户。
- 全 deck `needs_human` 页 >30% → 停手报告（大概率 spec_lock/模板层有系统性问题）。

## 三、概念终审（一票否决，最后做）

全部截图通过 rubric 后，回答两问：
1. **换名测试**：把主题换成竞品/别家产品，这份 deck 还成立吗？
   成立 = 内容空心（只有正确的样式没有具体的事实），回 outline 层补 evidence，不是改样式。
2. **一句话论证**：这份 deck 的视觉母题来自内容的哪里？（spec_lock Concept 段应已有答案，对照截图检验它真的体现了）

两问任一失败，属于**内容/概念问题**，禁止用视觉修补掩盖。
