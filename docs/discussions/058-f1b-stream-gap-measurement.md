# 058 · F1b 断流正文缺口的量化（2026-07-30）

> 结论先说：**F1b 比 ADR-071 的措辞严重得多** —— 不是「缺一段」，而是断流跨越回合结束时**丢失起点之后的几乎全部正文（实测 97.7%）且永不自愈**。
> 配套：ADR-071 §遗留 F1b · gotchas §20① · 量化 harness 在 scratchpad（`measure-f1b-gap.ts` + `cuttable-proxy.ts`，**未入库**）。

## 为什么要先量化

ADR-071 把 F1b 列为遗留，理由是「要动 `use-session-messages` 的分页合并，那里有明确注释警告重新 seed 会打乱分页顺序并复活已 revert 的轮次」。
但**没人量化过缺口有多大**。而 LaTeX P1 的教训正是：前三版都在防御一个从未用真实语料验证过的副作用，实测误伤 0 —— 前提本身不成立。
所以先测再决定为它付多少复杂度。

## 方法

真 GUI（Vite + 真 opencode + headless Chrome）+ mock LLM 流 300 个 `M0001…M0300` marker（约 36s 一轮）。
断流在 t≈2s 开始，**在传输层真实切断**，回合结束后对比三个数：界面所见 / 服务端真相 / 切走切回后。

## 实测

| 断流时长 | 重连时 | 回合结束时 | 服务端 | 切走切回后 | **缺失** | 断连横幅 |
|---:|---:|---:|---:|---:|---:|:--|
| 8s | 7 | **300** | 300 | 300 | **0** | 无 |
| 20s | 7 | **300** | 300 | 300 | **0** | 无 |
| 45s | 7 | **7** | 300 | 300 | **293（97.7%，约 1758 字符）** | 有 |

## 结论：严重程度不取决于断流时长，而取决于**是否跨越回合结束**

- **断流落在回合内**（8s / 20s）：**完全自愈**。恢复后继续到来的事件把正文补齐，缺失 0。这解释了为什么这个缺口一直没被发现 —— 日常抖动都在这一档。
- **断流跨越回合结束**（45s）：**丢 293/300，且永不自愈**。恢复时回合已完成，再没有任何事件会到来。界面停在断流那一刻的第 7 个词，服务端有完整 300。

**触发条件并不罕见**：合盖休眠、切 Wi-Fi、VPN 重连都是几十秒量级；而 **sidecar 崩溃（ADR-071 的原始故障链）必然跨越回合结束**，因为回合随进程一起死了。

**用户无从察觉**：横幅正确弹出（45s 那行 `banner=yes`），所以用户知道断过 —— 但没有任何迹象表明正文没补回来。切走再切回能补齐，可那是没人会想到的操作。

## 修法边界（数据把危险区排除掉了）

**不需要碰那个危险的分页合并。** `use-session-messages.ts` 的注释写明：*「Only consult the cache while the turn is in flight (busy). Idle sessions trust the snapshot fully, so a revert can't be undone and paginated history can't be reordered.」*

而本缺口的成立条件恰好就是**回合已结束 ⇒ 会话 idle**。所以：

> 在 `reconnectEpoch` 变化、且该会话**已 idle** 时，重跑一次 `fetchHistory` 的合并。

危险的是「turn 在飞时重新 seed」，这个场景不在其中。回合内断流本来就自愈，不需要也不应该动。

**待设计的细节**：`fetchHistory` 的 effect 现在只依赖 `sessionId`，且入口处 `setMessages([])`；直接复用会清空并重置分页窗口（用户已加载的更早历史会消失、视口跳动）。需要一条「不重置、只合并」的路径。

## 两次纠错（都是非空转门抓住的，方法论价值大于结论）

1. **Playwright 的 `setOffline` 不切 loopback 流量。** 第一版测出 `missing=0`，但门禁警告「没看到断连横幅」。补上「断流期间界面是否停止增长」的检查后实测 **`ui 7→66`** —— 网络从没断过，那份 `missing=0` 是一份关于空转的报告。改用可切断的 TCP 代理（插在 Vite 与 opencode 之间，renderer 无需改配置、CORS 不变）才真正断流。
2. **场景选错也会得出「无缺陷」。** 换成真断流后，8s 那档仍是 `missing=0` —— 因为回合还在跑，后续事件补齐了。必须让断流**覆盖回合结束**才够到 F1b。

任一步停下都会得出「F1b 不存在，不用修」。

## 顺带发现

`e2e/switchback-gap.e2e.ts` 用 `getByRole("button", { name: /马上开始|开始|send/i })` 定位首页 CTA。headless Chrome 报 en-US ⇒ 界面渲染英文（"Start Now"），且该 CTA **不是 `<button>` 元素** ⇒ 该选择器现在找不到元素。那个 harness 应已跑不动，需单独修。
