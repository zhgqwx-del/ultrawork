# 生成验收记录

1. 读变更范围、确认后的规格、测试计划和已有证据。结合实际差异按受影响的 AC 选择定向用例、回归和手工检查；可复用项目的模块到场景映射，补充本次特有的边界，按 ID 去重。定位实际受测入口、HEAD 及未提交差异，不因分支名或技术栈套用固定命令。
2. 按仓库约定执行检查，记录命令、退出状态、用例数量、环境、数据、受测 SHA 或工作区状态。分别标明行为断言失败、超时或环境阻塞、跳过及未执行。预期执行测试却发现零条用例时，记录发现问题，不能仅凭退出码 0 填写验收通过。测试失败仍生成报告，能独立执行的检查继续；本技能不为得到通过结果修改业务代码或断言。
3. 手工验收按场景给出最小步骤、数据和预期；可按模块分批核验。实际观察或用户明确提供的实测结果写明执行人和环境，未操作、跳过或不明确的结果标为待验证。复用旧测试产物前核对其版本、运行环境和场景适用性，不能把未绑定版本的历史截图或缓存报告当作当前通过证据。
4. 使用 `docs/stdd/templates/verification.md` 汇总场景结果和复跑入口，保留仍相关的历史记录及其版本。明确已验、失败、阻塞和待验范围，跳过项不计为通过；是否可合入或交付沿用项目约定。rebase 或实现变化后核对证据适用性，按项目要求复跑并更新受测状态；修复工作交回对应实现任务。
