# 缺陷诊断与回归准备

1. 从任务已授权的工单、日志、截图和本地代码收集证据，沿用项目反馈平台及访问方式。记录来源、发生时间与时区、应用版本、必要环境和复现数据；区分已取得、缺失和无法读取的资料。日志优先定位问题时段及请求或会话标识，避免把其他运行的最新日志当作本次证据。引用使用脱敏片段或原系统链接。
2. 对照对应版本的规格，按时间线关联报错、输入、版本和调用链。本地代码与反馈版本不同时注明差异。缩小复现数据，记录预期、实际结果、受影响版本和稳定的测试入口，用正常样本核对影响边界。将已复现事实、根因假设和下一步验证分别写清；尚未复现时交付当前证据和复现入口，不把推断标为确认结论。
3. 使用 `docs/stdd/templates/diagnosis.md` 记录诊断，可以合入现有工单。将能区分错误行为与正确行为的样例写成或关联一个 `AC-*`。
4. 交付最小复现、影响范围和修复方向。需要实施时，把回归场景与实施方案交给 `stdd-start` 或按已有确认记录进入 `stdd-delivery`。
