# 内容工程 — Research 阶段 + 事实溯源 + 内容厚度（言之有物的三件套）

> 核心原则（凌驾一切流程）：**事实验证先于假设**。涉及具体产品/版本/数字/时间线的断言，
> 能查证的必须先查证，禁止凭训练记忆断言（❌「我记得 X 还没发布」）。
> **诚实占位 > 编造**：没有事实支撑的数据，用占位标注，绝不编数。

## 一、Research 阶段（无源文档时 MANDATORY，有源文档时补缺）

触发条件：用户只给了主题/要求，没给文档；或源文档覆盖不了大纲需要的事实。

1. 把主题拆成 3-6 个检索问题（是什么/关键能力/数据与规模/对比与生态/最新动态）。
2. 用可用的联网工具（websearch / webfetch）逐个检索，**至少 3 轮**；无联网工具时必须
   明确告知用户「内容将基于模型知识，具体数字/时间线可能过时」并建议提供素材。
3. 产出两个文件到 `<project>/research/`：
   - `research.md` — 结构化调研笔记（按检索问题分节，含引文）
   - `facts.json` — 事实清单，outline 引用的唯一来源：

```json
[
  { "fact_id": "F1", "claim": "opencode 是开源的终端 AI 编码 agent，GitHub ★数 …",
    "source_url": "https://…", "date": "2026-07-18" }
]
```

规则：一条外部主张一个不可变 `fact_id`；同一主张多来源可并列 `source_url`；
查不到可靠来源的主张**不进 facts.json**（宁缺毋滥）。

## 二、outline 的 evidence 契约（内容厚度的结构保障）

每个**正文页**（非封面/章节/引言/收尾）必须有：

| 字段 | 要求 |
|---|---|
| `takeaway` | 断言句标题素材：含数字或明确谓语的结论（「X 使 Y 提升 31%」），**不是**话题词（「市场概览」❌） |
| `evidence` | ≥2 条支撑点，每条引用 `fact_id`，或 `"source":"user-doc"`（源文档），或 `"scenario":true`（虚构示意） |
| `confidence` | high / medium / low（自报；low 页交付摘要里列给用户） |
| `speaker_notes` | 讲稿：说页面上**没有**的话（论证/过渡/预答问题），禁止复读 bullet |

**scenario 规则**：标 `"scenario":true` 的数据页，渲染时页脚必须出现可见标注
（如「示意数据（scenario）」）——绝不冒充真实。

## 三、反内容 slop（validate_outline 硬拦）

- **空话黑名单**（takeaway/evidence 命中即错）：赋能、抓手、闭环、降本增效、全面提升、
  更快更强、极致体验、革命性、颠覆式——除非后面紧跟具体数字/事实。
- **data slop**：正文出现具体数字而 evidence 无 fact_id 支撑且未标 scenario → 错。
- **quote slop**：引言页的引文必须有出处（fact_id 或用户提供），禁止编造用户评价。
- 弱标题 lint（pyramid mode）：标题是名词短语且不含数字 → warning。

## 四、concept 一票否决自检（spec_lock 前置五问）

写 spec_lock 前先回答（答案落 spec_lock 的 `## Concept` 段）：
1. 这份 deck 的叙事角色是什么（说服/汇报/教学/发布）？
2. 观众与内容的距离（决策者远观 / 从业者细读）？——**这一问直接决定 `delivery_purpose`**（见 §五）。
3. 视觉温度（冷峻论证 / 温暖叙事）？
4. 内容里最独特的意象/母题是什么？——**视觉母题必须从内容推导**，写一句
   「form 来自内容的哪里」；写不出 = 在套模板，重想。
5. **换名测试**：把主题换成别家产品这份大纲还成立吗？成立 = 内容太空，回炉。

## 五、内容密度与消费距离（`delivery_purpose`——通用性的核心，防"只有上界没下界"）

密度**不由题材/mode 决定**，由**消费距离**决定：观众是远观投影，还是拿去当文档近读？
这是任何 deck 都有的正交属性——同一份教学 deck，投影版该通风、讲义版该密集。`mode`
只管叙事/页序/语气，**绝不碰密度**（不硬编"教学就密、发布就疏"）。

- **`presentation`**（远观投影）：正文最短、每页要点最少、留白最多。airy 是*主动追求*的结果，**不是内容被砍**。
- **`balanced`**（缺省）：近似今日观感，通用默认。
- **`document`**（近读文档/讲义/白皮书）：正文最长、承载最密。字符预算与条目数上界随档放宽（表见 `outline-schema.md §字符预算`）。

### 5.1 容量估算（写 outline 前先算，别让 research 供给与渲染容量错配）
选定 `delivery_purpose` 后，先估**这份 deck 能装多少事实**：正文页数 × 每页要点数（见预算表）
× 每点承载。据此反推 research 该采集多深——供给远超容量则做减法（选最强证据），
供给不足则回 §一 补检索。**别在门禁上白白饱和**（研究再深，每点仍只显示预算内的字）。

### 5.2 内容下界（O9 dense 底 + 学术扩词，与上界对称）
渲染侧长期"只有上界没下界"，导致内容被压薄。补两条下界：
- **O9 dense 页下界**（`validate_outline` 出 WARN，`visual-review R3` 判负）：凡 `rhythm:"dense"`
  的页，**主列表 ≥3 个要点 且 evidence ≥3 条**，否则"补点或换更密版式（densify）"。
  下界锚**条目数/证据数、不锚字数**——防 thin→bloated（灌水凑字数）。
- **学术/技术类扩词**：`document` 档下，学术/科学/工程/医疗主题的正文**本就该更长更实**
  （突破常规通风上限），字符预算已随档放宽到 42 承接。密不是错，空才是错。
